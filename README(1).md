# Haven — Sensory-Aware Navigation for Melbourne CBD

## Project overview

Haven is a sensory-aware wayfinding app designed for neurodivergent and
sensory-sensitive adults who commute in Melbourne's CBD. The app helps users
find routes with lower sensory load, instead of just the fastest route.

**Problem statement:** Sensory-sensitive adults rely heavily on public transport
but currently lack real-time, sensory-aware navigation tools to move through
Melbourne's dense CBD independently, especially during high-stimulation events
like construction, protests, or peak-hour crowding.

This project supports UN Sustainable Development Goal 11 (Sustainable Cities
and Communities), specifically Target 11.2 (Accessible Transit) and Target 11.7
(Inclusive Public Spaces). It is developed for FIT5120 (Industry Experience
Studio Project) at Monash University, S2 2026.

## Project scope

### Epic 2: Sensory Environment Monitoring

Give users real-time alerts about sensory stressors and nearby quiet spaces.

- US2.1 — Nearby sensory refuge locations (parks, libraries, quiet spaces)
- US2.2 — Predictive overcrowding alerts

## Current implementation

The AI pipeline currently predicts the condition of Melbourne street furniture
from asset type and location. A lower predicted condition is converted to a
higher sensory-risk score. This is different from the live pedestrian-stress
mock data shown in the prototype page.

## Run the complete pipeline

From the project directory:

```bash
source venv/bin/activate
python backend/scripts/preprocess.py
python backend/scripts/train_model.py
python run.py
```

Open <http://127.0.0.1:5000>. The page now calls the deployed model and loads
nearby refuge candidates from the three-source catalog. API endpoints are:

Do not open `frontend/index.html` with a `file://` URL. The page needs
the Flask API; otherwise report submission cannot connect. If the UI shows a
connection message, run `python run.py` and use the localhost URL above.

- `GET /api/health` - model readiness
- `GET /api/model-info` - training metadata and supported input values
- `GET /api/refuges` - nearby locations from three open datasets
- `POST /api/predict` - one street-furniture prediction
- `POST /api/predict-batch` - up to 100 predictions
- `GET /api/reports` - active, non-expired community reports
- `POST /api/reports` - validated, idempotent report submission
- `POST /api/reports/{id}/moderate` - token-protected hide/resolve/restore

The user interface also includes:

- device-persisted crowd/noise/roadwork preferences
- a two-step community-report flow backed by a real database
- automatic expiry and category filtering
- a transparent comparison of three conceptual route corridors

Route comparison is an assistive prototype, not road-network or turn-by-turn
navigation. It scores distance, active reports, nearby refuges, and preferences.

Example request:

```bash
curl -X POST http://127.0.0.1:5000/api/predict \
  -H 'Content-Type: application/json' \
  -d '{"asset_class":"Outdoor Furniture","asset_type":"Seat","latitude":-37.8136,"longitude":144.9631}'
```

Run the API tests with:

```bash
python -m unittest -v backend.tests.test_app backend.tests.test_pipeline
```

Evidence generated by the pipeline:

- `data/datasets/data_quality_report.json` - validation results for three sources
- `data/datasets/refuge_locations.csv` - standardised three-source location catalog
- `data/models/evaluation_report.json` - baseline, holdout, random/spatial CV,
  subgroup errors, feature importance, and limitations
- `docs/MODEL_CARD.md` and `docs/DATA_CARD.md` - intended use and governance summary

Do not use this model as evidence of real-time crowd or noise conditions. A
pedestrian-stress feature needs timestamped pedestrian counts, event, roadwork,
weather, and noise data plus a separately evaluated model.

## Database modes

Without `DATABASE_URL`, local development uses the ignored file
`data/database/sensepath.sqlite3`. This makes report submission persistent without
requiring Docker. Production uses the existing PostgreSQL schema when
`DATABASE_URL` starts with `postgresql://`.

## Container deployment

After copying `.env.example` to `.env` and changing both passwords/tokens:

```bash
docker compose up --build -d
docker compose ps
```

The web app will be available on `WEB_PORT` (default 5000). Do not deploy the
example PostgreSQL password or moderator token.
